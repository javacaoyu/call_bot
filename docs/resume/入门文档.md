# callbot 入门文档

> 面向第一次接触本项目的读者（同事 / 面试官 / 接手的开发者）。不深入代码细节，
> 目标是 20 分钟建立对项目的整体认知：它是做什么的、怎么运转的、有哪些核心概念。

---

## 一、项目是什么

**callbot 是一个外呼机器人（智能体）**——用一句话概括：

> 音频流进 → 智能体对话 → 音频流出

它是一个**实时流式语音对话引擎 + 话术编排平台**：

- **对话引擎**：客户说话被实时转写成文字，交给大模型（LLM）生成回复，再实时合成为语音播放回去——整个过程流式进行，第一句回复在几百毫秒内开口，客户可以随时**抢话打断**，机器人立即停嘴倾听。
- **话术编排平台**：非技术人员通过网页**拖拽流程图**（开场白 → 意图识别 → 处理节点 → 结束语），配合人设模板和行业模板库，几分钟配置出一个可用的外呼场景（催收、营销、回访等），发布即生效，支持版本回滚。

典型使用流程：**上传客户 → 选场景（或一键用行业模板）→ 点「外呼」→ 机器人自动开口 → 按流程图对话 → 说「再见」自动挂断** → 通话记录留档。

## 二、一次通话的完整生命周期

```
浏览器（操作台）                          后端（引擎）
    │ 选场景+客户，点「外呼」
    │ ──── offer（客户/人设/场景 ID）────→  加载该场景的已发布流程图
    │ ←── answer + 模型加载中状态 ────────  加载 ASR/VAD 模型
    │                                ┌── 模型就绪 → 执行流程「开场白」节点
    │ ←── reply 文本 + audio 帧 ──────┤    （配置了开场白就直读，否则 LLM 生成）
    │ 播放：「陈女士您好，我是…」
    │ ──── 16kHz PCM 二进制帧 ───────→  VAD 检测起音 →（若机器人在说话）打断！
    │                                │   ASR 流式转写「没空。」
    │                                │   VAD 检测静音端点 → 完整转写提交
    │                                │   意图识别：关键词命中「客户不耐烦」
    │                                ├→ 路由到对应处理节点（AgentScope 智能体）
    │ ←── reply 文本 + audio 帧 ──────┤   流式生成「就耽误您5秒钟…」
    │ ……（每说一句，重复：识别→路由→回复）
    │ 客户说「再见」
    │                                │   命中「结束通话」意图 → 播结束语
    │ ←── end 消息（结束语播完）──────┘   前端自动断开 → 通话记录落库（未接/接通）
```

一句话版：**每轮对话 = 意图识别 → 路由处理节点 → 流式回复 → 回到意图等待下一句**。

## 三、核心概念地图

| 概念 | 是什么 | 类比 |
|---|---|---|
| **三环节（ASR/LLM/TTS）** | 语音识别、大模型、语音合成，各自独立可切换 | 耳朵 / 大脑 / 嘴巴 |
| **打断（全双工）** | 客户在机器人说话时开口，机器人立即停嘴、记住已说的话 | 真人对话中的抢话 |
| **场景（Scene）** | 话术资产的组织单元：一个场景 = 1 张流程图 + 若干人设 + 若干工具 | 一个业务线（如「银行催收」） |
| **流程图（Flow）** | 话术逻辑的可视化编排：节点 + 连线；有草稿/发布/版本回滚 | 呼叫中心的接线脚本 |
| **意图（Intent）** | 客户一句话的语义分类，配置在意图连线上：名称 + 关键词 + 描述 | 「他说了啥 → 该谁接」 |
| **处理节点（Handler）** | 一个 AgentScope 智能体：自己的话术 prompt，可绑工具 | 坐席专员（投诉专员/催收专员…） |
| **人设（Persona）** | 机器人的人设与 system prompt，含开场白；挂在场景下 | 员工的人设与话术手册 |
| **变量插槽** | 模板中的 `{客户姓名}` 等占位符，外呼那一刻自动替换 | 邮件合并功能 |
| **工具（Tool）** | 处理节点可调用的能力：HTTP 配置式 / 代码插件 / 内置工具 | 坐席的查询系统 |
| **模板库** | 5 大行业（营销/催收/回访/通知/客服）的完整场景包，一键实例化 | 开箱即用的行业方案 |
| **通话记录** | 每次外呼的转写气泡流（客户/AI/打断标记）+ 状态（接通/未接） | 通话录音的文字版 |

## 四、节点与流程图（最需要理解的部分）

流程图只有 **4 种节点**，规则固定：

1. **开场白**（opening）：唯一入口，连接后先说；文本留空 = 用激活人设的开场白或 LLM 临场生成
2. **意图识别**（intent）：**每轮必经的中枢**；它的每条出边是一个意图（名称 + 关键词 + 描述），不带意图的出边是「兜底边」（至多一条）
3. **处理节点**（handler）：AgentScope 智能体，prompt = 人设打底 + 本节点话术追加；可绑工具、可开「吸附模式」（未命中关键词时留在本节点追问）；出边必须回连意图识别（形成循环）
4. **结束语**（end）：命中「结束通话」类意图后进入 → 播结束语 → 自动挂断

```
┌──开场白──┐        ┌──────────────┐
│          │───────→│              │──投诉──→ [投诉处理]──┐
└──────────┘        │  意图识别     │                     │
                    │  （中枢）     │──购买意向→ [促单处理]─┤
                    │              │                     │
                    │              │──结束通话→ [结束语] → 挂断
                    │              │──兜底──→ [主对话]────┘
                    └──────────────┘
```

## 五、关键设计思想（为什么这样做）

1. **延迟优先**：TTFT（首字响应时间）是第一指标——LLM 首 token 不等整句、遇到标点立即触发 TTS；意图先用**关键词本地匹配**（0ms），未命中才走 LLM 分类；每个节点的 system prompt 前缀字节级稳定，命中 DeepSeek 上下文缓存。
2. **打断的语义**：打断不只是「停」，还要「记得」——已完整说出的句子会以「打断占位」注入下一轮上下文，客户听到的回答不丢语境。
3. **AgentScope 的边界**：AgentScope 只做「纯文字进、纯文字出」的 LLM 编排与工具调用；语音引擎、状态机、流程图全部自建——保证可替换、可观测、确定性。流程图节点是**自建状态机节点**，AgentScope 智能体只在处理节点内部被调用；所有处理节点**共享一次外呼的同一个记忆状态**（换节点不换记忆）。
4. **音频走 PCM 直传**：WebRTC 只用于建立连接；音频不用 WebRTC 音轨（本项目实测 opus 解码损坏），浏览器以 16kHz PCM 二进制帧经 WebSocket 直传——简单、可控、低延迟。
5. **场景即外呼入口**：选场景 = 选定流程图 + 人设范围 + 工具范围；一切资产有归属、可审计。

## 六、部署与运行（概览）

- **环境**：WSL2 Ubuntu + RTX 4060 8GB；Docker 跑 PostgreSQL 16；Python 用 UV 管理、前端用 fnm 管理 Node
- **启动**：`docker compose up -d`（数据库）→ 后端 `uv run uvicorn callbot.api.app:create_app --factory` → 前端 `npm run dev`
- **测试**：后端 `uv run pytest`（215 用例）、前端 `npm test`（vitest）；静态检查 ruff / vue-tsc
- **文档**：[PRD](PRD.md)（产品需求）、[WBS](WBS.md)（排期与里程碑）、[函数注册表](函数注册表.md)（代码索引）、[工具插件规范](工具插件规范.md)（插件开发约定）、[local-models.md](local-models.md)（本地模型踩坑复盘）

## 七、目录结构速览

```
call_bot/
├── docs/              # PRD/WBS/函数注册表/入门/求职资料
├── src/callbot/
│   ├── channel/       # 接入层：WebRTC 信令 + 会话主循环（打断/收尾/落库）
│   ├── engine/        # 语音引擎：VAD / 会话状态机 / LLM→TTS 衔接器
│   ├── providers/     # 三环节 Provider：本地（FunASR/CosyVoice2）+ 云端（火山/千问）
│   ├── orchestration/ # 编排层：AgentScope 封装 + 共享状态多智能体 + 上下文管理
│   ├── flow/          # 话术引擎：流程图定义/校验 + 意图分类器 + 意图中枢状态机
│   ├── tools/         # 工具系统：代码插件加载器 + Toolkit 装配 + 内置工具
│   ├── templates/     # 行业模板库（5 行业场景包）
│   ├── api/           # FastAPI 路由（场景/流程/工具/人设/客户/通话记录/模板）
│   └── data/          # 数据层：SQLAlchemy 模型 + 变量渲染
├── frontend/src/      # Vue 3 管理台：对话工作台/流程图编辑器/各管理页
└── tests/             # pytest 后端测试
```
