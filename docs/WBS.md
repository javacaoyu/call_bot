## 1. 说明与估算假设

### 1.1 WBS 分解原则

- 按「阶段 → 工作包 → 任务」三级分解，任务为可交付的最小工作单元；
- WBS 编号：`阶段号.工作包号.任务号`；
- 每个任务标注：任务描述、交付物、依赖、工期（人日）。

### 1.2 估算假设

| 假设 | 说明 |
|---|---|
| 人员 | 单人全职开发 |
| 人日 | 1 人日 = 8 小时有效工作时间 |
| 时间 | 无外部时间限制，按理想连续进度估算 |
| 环境 | RTX 4060 8GB 本地推理；Docker(WSL Ubuntu) 跑 PostgreSQL+pgvector |
| 模型 | 开发期 LLM=DeepSeek 云端；ASR=FunASR 本地；TTS=CosyVoice2-0.5B 本地 |

> **估算为理想值**。单人开发需学习 AgentScope / WebRTC / CosyVoice2 等并踩坑，建议总工期按 **1.3~1.5 倍**预留。

## 6. 资源与风险

| 项 | 说明 |
|---|---|
| 人力 | 单人，建议阶段 3/6/9/10 重点攻坚 |
| 硬件 | RTX 4060 8GB（本地推理）；并发扩展需多卡/云端 |
| 外部依赖 | DeepSeek API、云端 ASR/TTS 厂商 API Key（需开通） |

| 风险 | 影响阶段 | 应对 |
|---|---|---|
| AgentScope 学习/踩坑 | 阶段 2 | 预留缓冲；编排层接口隔离，可回退自建 |
| WebRTC 回声/延迟 | 阶段 2–3 | 浏览器 AEC；降噪调优 |
| 全双工打断体验 | 阶段 3 | 单独攻坚，灵敏度可配 |
| RAG 检索延迟超标 | 阶段 7、9 | HNSW + 小 top-k + rerank 跳过 + 检索缓存 |
| 边说边想复杂度高 | 阶段 9 | 接口隔离，可降级为纯流式 |
| 本地 TTS 并发瓶颈 | 阶段 10 | 多卡/多实例/切云端 |
| 合规政策变动 | 阶段 8 | 规则配置化，快速适配 |
