# 工具插件规范（WBS 6.3 工具库）

> 工具双轨：**① 代码插件**（本文件规范）与 **② HTTP 配置工具**（WebUI 表单配置，运行时动态生成）。
> 两者共用注册表、按场景分类、均可被流程图中 handler 子智能体绑定。

## ① 代码插件规范

### 存放位置与命名

- 目录：`src/callbot/tools/plugins/`
- **文件名 = 工具名**（snake_case，如 `query_order.py`）

### 四要素约定（模块必须暴露）

| 要素 | 类型 | 说明 |
|---|---|---|
| `TOOL_NAME` | `str` | 注册名（与文件名一致） |
| `TOOL_DESCRIPTION` | `str` | 给 LLM 看的用途说明——**必须写清「何时该用」**，这是 LLM 决定是否调用的唯一依据 |
| `Params` | `ParamsBase` 子类 | 参数 schema，自动转 JSON schema 给 LLM 填参；字段用 `Field(description=...)` 说明语义 |
| `run` | `async def run(形参与 Params 字段一一对应) -> str` | 执行体，任意 Python 逻辑 |

> ⚠️ **AgentScope 2.0.12 以 `**kwargs` 扁平调用工具函数**（实测：传 params 实例会
> TypeError）——`Params` 类只作 JSON schema，`run` 的形参必须与 `Params` 字段
> 一一对应（或收 `**kwargs`）；加载器会校验并跳过不符的插件。

### 示例

```python
"""订单查询工具：按订单号查订单状态。"""
from agentscope.tool import ParamsBase
from pydantic import Field

TOOL_NAME = "query_order"
TOOL_DESCRIPTION = "按订单号查询订单状态与金额，参数 order_id 为订单号"

class Params(ParamsBase):
    order_id: str = Field(description="订单号，如 20261123001")

async def run(order_id: str) -> str:
    ...
    return f"订单 {order_id} 状态：已发货，金额 128 元"
```

### 执行与返回约定

- **返回自然语言文本**（拼进对话上下文供 LLM 引用），不要返回原始 JSON
- `run` 内捕获异常并返回「工具执行失败：原因」文本（LLM 能看到失败信息并换策略），不要向调用方抛异常
- `run` 必须 async；HTTP 调用须设超时（建议 `asyncio.timeout(5)`），禁止长阻塞
- 参数类型只用 pydantic 基础类型（str/int/float/bool 及可选类型）

### 加载与生效

- 后端**启动时** `importlib` 扫描 `plugins/` 目录注册进内存注册表
- **修改插件需重启后端生效**；新依赖必须写入 `pyproject.toml`（`uv sync` 会重置 venv，勿用临时 pip install）
- 启动加载后经 WebUI「从插件导入」进工具库（选择场景归属）；`GET /api/tools/plugins` 列出已加载插件

## ② HTTP 配置工具（零代码）

- 工具库页面表单：名称 / 用途说明 / URL（支持 `{参数}` 路径占位）/ 方法（GET/POST）/ 参数表（名称/类型/必填/说明）/ header（如 API key）
- 运行时动态生成 ParamsBase + 通用 HTTP 执行函数注册进 Toolkit
- **改配置即用，无需重启**

## 语义与安全

- **工具结果是资料不是朗读稿**：handler 的 prompt 模板内置约束「用工具查询的信息用自己的话回答，不朗读 JSON/字段名」；工具输出仅参与 AgentScope ReAct 循环，流式吐出的文本才进 TTS
- 插件目录由管理员维护（自部署产品）；HTTP 工具的 header 可存 API key（风险水平与 provider key 同级的本地部署）
